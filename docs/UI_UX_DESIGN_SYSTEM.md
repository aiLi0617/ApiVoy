## 3. 产品与设计方向

ApiVoy 是本地优先的多协议开发者工具。界面采用“IDE + 高密度数据工作台”模式，强调紧凑、稳定和键盘友好。Hoppscotch 仅作为操作效率参考，不复制其品牌或具体组件样式。

- 使用清晰层级和稳定结构，避免装饰性大卡片、复杂渐变和营销式大标题；
- 采用 8px 基础间距，工作台主要间距为 8–16px；
- 主操作必须明确，次要操作不能争夺视觉焦点；
- 请求上下文、执行状态和响应指标保持在稳定位置；
- 状态不能只依赖颜色，必须配合文字或图标；
- Web 和 Tauri 统一使用 `@apivoy/ui`。

## 5. 设计令牌

令牌集中在 `packages/ui/src/styles.css`，新增组件必须使用语义令牌。

| 令牌 | 深色基准 | 用途 |
|---|---:|---|
| `--apivoy-bg` | `#0b0d10` | 应用画布和代码表面 |
| `--apivoy-nav` | `#101216` | 顶部栏与导航 |
| `--apivoy-workspace` | `#111419` | 主工作区 |
| `--apivoy-bg-elevated` | `#171a20` | 输入框、列表行和普通面板 |
| `--apivoy-overlay` | `#1d2128` | 对话框和命令面板 |

- UI 使用 IBM Plex Sans 等无衬线字体；代码和协议数据使用 JetBrains Mono 等等宽字体；
- 微交互控制在 150–250ms，禁止 hover 缩放造成布局抖动；
- 必须支持 `prefers-reduced-motion`；
- 仅使用既定层级：顶部栏 `20`、下拉层 `30`、拖拽层 `40`、对话框 `50`、Toast `60`。

## 7. 工作台实施要求

- 🟡 表单提供可见标签并正确关联错误；
- 🟡 超过约 300ms 的操作显示加载反馈；
- 🟡 空页面提供解释和下一步操作；
- 🟡 删除或不可逆操作使用统一确认 Dialog；
- 🟡 成功操作使用统一 Toast 或稳定状态区；
- 🟡 宽表格只在自身容器滚动；
- 🟡 超过约 100 项的长列表进行虚拟化；
- 🟡 使用共享 SVG 图标并清理旧字符图标；
- 🟡 所有交互元素具有 hover 和 `focus-visible` 状态。

HTTP 是当前参考样板：请求配置和响应检查器位于可持久化的 `SplitPane` 中。
