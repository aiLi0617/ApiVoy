## 3. 产品与设计方向

ApiVoy 是本地优先的多协议开发者工具。界面采用“IDE + 高密度数据工作台”模式，强调紧凑、稳定和键盘友好。Hoppscotch 仅作为操作效率参考，不复制其品牌或具体组件样式。

- 使用清晰层级和稳定结构，避免装饰性大卡片、复杂渐变和营销式大标题；
- 采用 8px 基础间距，工作台主要间距为 8–16px；
- 主操作必须明确，次要操作不能争夺视觉焦点；
- 请求上下文、执行状态和响应指标保持在稳定位置；
- 状态不能只依赖颜色，必须配合文字或图标；
- Web 和 Tauri 统一使用 `@apivoy/ui`。

## 4. 信息架构

共享壳层包含紧凑顶部栏、资源管理器、协议导航和主工作区。

| 分组 | 工作台 |
|---|---|
| API | HTTP、GraphQL、gRPC、SOAP/RPC |
| 实时通信 | WebSocket、SSE、TCP/UDP |
| 消息 | MQTT、AMQP、Kafka |

## 5. 设计令牌

令牌集中在 `packages/ui/src/styles.css`，新增组件必须使用语义令牌。

| 令牌 | 深色基准 | 用途 |
|---|---:|---|
| `--apivoy-bg` | `#0b0d10` | 应用画布和代码表面 |
| `--apivoy-nav` | `#101216` | 顶部栏与导航 |
| `--apivoy-workspace` | `#111419` | 主工作区 |
| `--apivoy-bg-elevated` | `#171a20` | 输入框、列表行和普通面板 |
| `--apivoy-overlay` | `#1d2128` | 对话框和命令面板 |

- UI 使用 IBM Plex Sans 等无衬线字体；代码和协议数据使用 JetBrains Mono 等等宽字体；
- 微交互控制在 150–250ms，禁止 hover 缩放造成布局抖动；
- 必须支持 `prefers-reduced-motion`；
- 仅使用既定层级：顶部栏 `20`、下拉层 `30`、拖拽层 `40`、对话框 `50`、Toast `60`。

## 6. 图标系统

ApiVoy 使用单一产品 UI 图标体系：**Lucide**。选择依据是其克制的描边风格、`24 × 24` 网格、React 支持，以及与当前 IDE 型高密度界面的适配性。选型视觉样张见 [icon-library-comparison.html](icon-library-comparison.html)。

### 6.1 来源与边界

| 场景 | 允许来源 | 说明 |
|---|---|---|
| 导航、工具栏、表单、状态和普通业务操作 | Lucide | 通过 `@apivoy/ui` 共享图标抽象使用，不在页面内复制 SVG path |
| 第三方品牌或技术 Logo | 官方 SVG 或 Simple Icons | 仅当品牌识别确有必要；核对名称、颜色和商标要求 |
| ApiVoy 产品标志 | 仓库品牌资源 | 使用 `apps/*/public/apivoy-mark.svg` 等受控资产，不从通用图库替代 |
| Lucide 缺少的协议图标 | 同网格自定义 SVG | 必须经过设计评审，保持 `24 × 24`、`currentColor` 和统一描边 |
| 协议正文或流量数据 | 文本符号可保留 | 如消息方向 `←` / `→` 属于数据值时可以保留，不得借此充当按钮图标 |

不得新增 Tabler、Heroicons、Phosphor、Font Awesome、React Icons 或其他通用图标库来补单个缺口。确需更换主图标库时，必须作为独立设计系统变更评审，不能在页面级混用。

### 6.2 视觉规格

| 使用位置 | 图标尺寸 | 建议容器 | 说明 |
|---|---:|---:|---|
| 紧凑表格、输入框尾部和行内操作 | `14–16px` | `24–28px` | 优先保证小尺寸辨识度 |
| 工具栏、标签页、导航和普通按钮 | `18px` | `32–36px` | 默认规格，与当前共享 `Icon` 一致 |
| 空状态、功能入口和强调图标 | `24px` | `40–48px` | 不得通过图标替代标题或说明文字 |
| 品牌标志 | 按资产比例 | 按组件定义 | 不强制套用 Lucide 描边规范 |

- 使用 Lucide outline 作为默认风格，不混用 filled、duotone 或不同图标库的轮廓；
- 统一 `24 × 24` viewBox，描边基准为 `1.8`；引入官方组件后由共享包装层设置，不在页面传入任意 `strokeWidth`；
- 使用 `currentColor` 继承语义颜色，禁止在 SVG 内硬编码主题色；
- 图标与文字并排时保持视觉基线和 `6–8px` 间距；同组操作必须使用一致尺寸；
- hover、active、disabled 和 danger 状态由按钮或父组件控制，不在图标内部建立私有颜色状态；
- active 状态优先改变颜色、背景或边框，不随意从 outline 切换为 filled，避免视觉跳变。

### 6.3 语义命名与实现

页面继续使用共享语义 API，例如 `<Icon name="search" />`，由 `packages/ui/src/Icons.tsx` 维护显式映射。映射层负责固定尺寸、描边、ARIA 默认值和 Lucide 组件导入，页面不得直接依赖图库命名细节。

- `IconName` 使用稳定的产品语义，如 `search`、`send`、`database`、`settings`；
- 显式导入并映射使用到的 Lucide 组件，禁止 `import * as Icons` 后动态索引，以免破坏 tree-shaking；
- 同一动作只保留一个默认图标，例如删除统一映射到 `Trash2`，不能在不同页面混用 `Trash`、`X` 和字符 `×`；
- 工作台图标表达协议类别或工作方式，不承诺复刻协议 Logo。推荐语义包括：HTTP=`Globe2`、gRPC=`Network`、WebSocket=`RadioTower`、Redis/SQL=`Database`、Runner=`Play`、Gateway=`Route`、Capture=`ScanSearch`、Plugins=`PlugZap`、AI=`Bot` 或 `Sparkles`；
- 自定义图标必须加入同一映射层，并记录为何 Lucide 现有图标无法表达该语义。

### 6.4 无障碍与交互

- 图标与可见文字同现时，SVG 默认 `aria-hidden="true"`，避免重复播报；
- 纯图标按钮必须在按钮上提供明确的 `aria-label`，`title` 只作辅助提示，不能代替可访问名称；
- 状态不能只依赖图标或颜色，错误、警告、成功和运行中状态必须同时提供文字或可访问文本；
- 可点击目标遵守最小容器尺寸和 `focus-visible` 规则，不能把裸 SVG 直接作为交互元素；
- 加载图标的动画必须遵守 `prefers-reduced-motion`。

### 6.5 禁止与迁移清单

禁止使用 emoji、Unicode 字符或字体字形充当交互控件，包括 `•••`、`↑`、`↓`、`⧉`、`×` 和 `✓`。CSS `content`、mask data URI 和页面私有手写 SVG 也不得成为新的常规图标来源。

现有迁移按以下顺序执行：

1. 将共享 `Icon` 的手写 path 映射迁移到 `lucide-react` 显式组件映射；
2. 替换按钮中的 `•••`、`↑`、`↓`、`⧉`、`×`、`✓` 等字符图标；
3. 收敛 `WorkbenchFrame` 分栏图标、CSS mask 和 data URI 图标；
4. 复核 WebSocket、SSE、TCP/UDP 中的方向符号，只保留属于消息数据的文本符号；
5. 验证深浅主题、16px 小尺寸辨识度、键盘焦点和屏幕阅读器名称；
6. 变更依赖时同步许可证声明，并按依赖变更执行维护者 PR 检查清单。
