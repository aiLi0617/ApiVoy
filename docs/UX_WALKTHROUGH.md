## 3. 目标信息架构（建议）

| 区域 | 应承载 | 现状 |
|------|--------|------|
| 资源管理器 | 工作区 / 项目 / 集合 / 请求；导入导出；集合 **运行** | 无 Run；导入仅在此 |
| 协议导航 | 仅协议工作台（API / 实时 / 消息 / 数据） | 工具 + 协作也挤在同一轨 |
| 工具 | Mock、Capture、Gateway 任务、Runner（可选面板） | 与协议同级 tab |
| 账户 / 协作 | Team、成员、同步；SSO 为登录方式；Comments 为侧栏 | 三个独立「协议」tab |
| Settings | 主题、语言、协作 URL、AI/Gateway 凭据、插件 | 仅主题/语言在顶栏 |
| 工作台工具条 | 发送、保存、Code、环境指示 | HTTP 相对完整，其余碎片化 |

| **状态** | done |
| **维度** | 放置 / 交互 |

**边界**：调试当前聚焦请求生命周期与事件时间线，不提供断点、单步执行或脚本逐句调试；后续若增加完整调试器，应作为独立面板而不是继续堆叠按钮。

| 日期 | 说明 |

### UX-043 HTTP Headers 录入效率低且 Body 输入区会消失

| 字段 | 内容 |
|------|------|
| **等级** | P1 |
| **状态** | done |
| **维度** | 交互 |
| **模块** | `HttpWorkbench.tsx`、`styles.css` |

**问题**：Headers 以整段 `Name: Value` 文本录入，新增、修改和删除单项时容易破坏格式；GET / HEAD 下 Body 页签直接替换成提示文案，用户看不到输入位置，也无法确认已有 Body 草稿是否仍被保留。

**理想**：Headers 使用逐行 Key / Value 编辑，可直接新增和删除；最后一行输入后自动补空行。Body 编辑器在所有方法下保持稳定可见，不适合发送 Body 的方法只提示发送规则，不移除或清空输入内容。

**实现**：Headers 改为带稳定行标识的 Key / Value 编辑器，空行不参与发送，并提供显式新增和删除；Body 编辑器固定展示，GET / HEAD 下保留内容并显示方法提示，切换到支持请求体的方法后可继续使用原草稿。

**边界**：GET / HEAD 当前仍不会把 Body 发送到执行端；本次只保证编辑内容可见且不会因方法切换丢失。

**变更记录**

| 日期 | 说明 |
|------|------|
| 2026-08-13 | Headers 改为 Key / Value 行编辑并恢复常驻 Body 输入区；状态 done |

### UX-044 HTTP Body 缺少内容类型选择与编码联动

| 字段 | 内容 |
|------|------|
| **等级** | P1 |
| **状态** | done |

| **模块** | `HttpWorkbench.tsx`、`styles.css` |

**问题**：Body 只有 Raw 与 Multipart 两种选择，Raw 无法表达实际内容类型，也不会帮助用户同步 Content-Type；URL 编码表单仍需手写编码字符串。

**理想**：Body 内提供 none、form-data、x-www-form-urlencoded、JSON、XML、Text、GraphQL 等可横向浏览的类型选择；选择类型时同步 Content-Type，并为结构化表单提供 Key / Value 编辑器。

**边界**：Binary 与 msgpack 需要请求模型和 HTTP Driver 支持原始字节，不能用 UTF-8 字符串或伪 Base64 入口替代；本次不纳入完成范围。
